## LocalStack planning rule

ADR-012 is authoritative:

- LocalStack is the only infrastructure/runtime target;
- no task requires a real AWS account for development, staging, validation, or deployment;
- AWS account/region selection, IAM/OIDC federation, AWS Budget/credit controls, Cost Explorer, cloud execution authorization, real-cloud preview/staging/production, and AWS teardown evidence are obsolete planning gates;
- AWS-style service names identify capability mappings for learning and remain usable only where LocalStack supports the named scenario sufficiently;
- unsupported, partial, edition-dependent, or behaviorally different LocalStack features must be recorded as limitations instead of silently claiming AWS compatibility;
- Domain/Application code remains independent of LocalStack-specific endpoints, credentials, SDK configuration, and feature switches;
- endpoint overrides, synthetic credentials, region/account placeholders, ports, resource prefixes and emulator feature flags remain runtime/infrastructure configuration.

The legacy `cloud_verification` field remains temporarily for orchestrator/schema compatibility. Under ADR-012 it means **infrastructure-sensitive LocalStack verification**, never permission or requirement to use real AWS.

## Readiness rules

Task maturity remains:

```text
Outline -> Refined -> Ready -> Active -> Completed
```

- **Outline** — useful future node; not executable.
- **Refined** — implementation shape is materially understood, but a dependency/evidence gate remains.
- **Ready** — Builder can execute without inventing business or architecture decisions.
- **Active** — an already-Ready task is currently claimed.
- **Completed** — accepted result is present on authoritative `main` with verification evidence.

Dependencies, human/product/domain/architecture/security gates, and exclusive-resource conflicts fail closed. Real-AWS execution is not a valid gate under ADR-012.

## Replanning decisions caused by ADR-012

The domain/business task graph is intentionally preserved. The infrastructure decision changes technical execution and validation, not business semantics.

Key plan changes:

The obsolete AWS development deployment/cost task became the TASK-0094 LocalStack lifecycle;
- obsolete AWS OIDC/preview/dev pipeline task became `TASK-0095` CI LocalStack verification;
- real AWS account/Budget/IAM/OIDC/cost gates are removed from readiness;
- storefront delivery is validated against LocalStack-supported static-delivery/cache capabilities rather than a real CloudFront deployment;
- Mock Payment and workflow tasks execute locally against explicit external-like/runtime boundaries;
- performance hardening measures correctness, latency, throughput and local resource pressure without treating LocalStack results as AWS capacity/cost evidence;
- staging hardening means an isolated **staging-like LocalStack profile**, not a cloud staging environment;
- observability hardening uses representative local runtime signals and no longer depends on Cost Explorer;
- custom-domain work may model host ownership/routing locally, while public DNS/certificate issuance is outside scope unless ADR-012 is later superseded.

## Important architecture invariants unchanged by replanning

- modular serverless monolith remains the target shape;
- module/persistence ownership remains explicit;
- trusted Tenant read/mutation/platform/public contexts remain unchanged;
- no cross-domain table shortcuts or transactions;
- conditional writes/transactions protect local invariants;
- async consumers remain at-least-once and idempotent;
- ADR-006 outbox/reliable-fact pattern remains authoritative;
- ADR-010 order orchestration semantics remain authoritative;
- ADR-011 refund choreography remains authoritative;
- Accounting remains append-only, balanced and source-idempotent;
- business/domain gaps remain blockers even though the infrastructure target became local.
