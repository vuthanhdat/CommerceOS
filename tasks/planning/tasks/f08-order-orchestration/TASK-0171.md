## Objective
Make interrupted/ambiguous order workflow executions recover without duplicate owner effects or guessed financial outcomes.

## Scope
Wait/retry/backoff bounds; Payments reconciliation loop; durable workflow status/projection; operator retry/resume where safe; NeedsAttention when bounded automation cannot resolve; redrive/duplicate task behavior.

## Out of scope
Manual operator declaration of payment success/failure, time-based release of Unknown stock hold.

## Inputs
PD-018, ADR-010, queue/workflow rules.

## Expected changes
Workflow/status/recovery composition and tests.

## Implementation steps
Define operational statuses, reconciliation polling/continuation, bounded retry policies, operator-safe actions, simulate crash/restart/duplicate delivery.

## Acceptance criteria
- [ ] Reserved stock remains held while payment outcome is Unknown.
- [ ] Time passage alone never resolves Unknown or releases stock.
- [ ] Duplicate workflow/task delivery cannot duplicate reservation/capture/confirmation.
- [ ] Bounded unresolved cases become NeedsAttention with correlation/evidence.
- [ ] Recovery resumes owner contracts rather than editing owner state directly.
- [ ] Redrive preserves logical source identities.

## Verification
Failure-injection/clock/replay tests; harness.

## Architecture / security / reliability / observability / local runtime
Operational state clearly labeled non-business authority. Actionable diagnostics include execution/order/payment correlation.

## Risks and edge cases
Provider remains pending indefinitely.

## Open questions
Operator may inspect/escalate but not override provider truth in MVP.

## Completion report
Completed 2026-08-14. Unknown workflow recovery reconciles the existing payment operation and transitions to NeedsAttention only after bounded unresolved evidence.
