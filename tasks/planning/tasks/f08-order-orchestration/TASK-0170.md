## Objective
Implement the approved durable workflow from OrderPlaced through reservation, payment/reconciliation, Sales confirmation and allocation using application contracts only.

## Scope
Deterministic execution identity/start outbox; Step Functions-style definition; Inventory reserve task; Payments capture/inquiry task; Sales confirm/allocate tasks; definitive decline path; retry/catch rules.

## Out of scope
Accounting posting, refund choreography, business truth stored only in workflow history.

## Inputs
ADR-010, integration matrix, owner contracts.

## Expected changes
Workflow definition/CDK, composition handlers/adapters, Sales start relay and tests.

## Implementation steps
Define state machine against approved facts, stable execution/start dedupe, task request/result contracts, branch on Captured/definitive no-commit/Unknown, tests for replay and interruption.

## Acceptance criteria
- [ ] One logical Order process starts at most once or duplicate start is harmless.
- [ ] Workflow calls owner application contracts, never tables.
- [ ] Captured -> Sales Confirm -> Allocated only after required reservation evidence.
- [ ] Definitive decline/no-commit does not fabricate cancellation/release and permits approved later payment retry state.
- [ ] Unknown enters reconciliation/wait, not failure branch.
- [ ] Technical timeout/retry exhaustion cannot become Payment failure or stock release by itself.

## Verification
Definition/unit/task-contract tests; LocalStack execution deferred to TASK-0172; harness.

## Architecture / security / reliability / observability / local runtime
Workflow is operational coordinator, not domain owner. Correlation/causation/execution IDs retained.

## Risks and edge cases
Duplicate task callbacks; execution restart; LocalStack Step Functions fidelity.

## Open questions
None; ADR scope accepted.
