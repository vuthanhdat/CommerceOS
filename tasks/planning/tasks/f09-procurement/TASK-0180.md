## Objective
Establish Procurement ownership for Suppliers and PurchaseOrder commitment with immutable Submitted snapshots.

## Scope
Procurement module/table; Supplier Active/Archived; PO Draft/edit/submit; eligible Draft/Published Product references; immutable supplier/lines/terms after submit; conditional cancel before downstream evidence; tenant queries.

## Out of scope
Inventory receipt, invoice/payment, tax/freight/discount calculations.

## Inputs
Procurement domain baseline.

## Expected changes
Procurement Domain/Application/Infrastructure/CDK/tests.

## Implementation steps
Model aggregates/states, tenant-scoped persistence, Product eligibility query via Catalog contract, submit snapshot/revision/idempotency, cancellation preconditions.

## Acceptance criteria
- [ ] New PO requires Active Supplier and non-Archived eligible Product.
- [ ] Submitted supplier/line/quantity/commercial terms cannot be edited in place.
- [ ] Cancellation is rejected after confirmed receipt/invoice/payment evidence exists.
- [ ] Supplier name is not treated as legal/global uniqueness key.
- [ ] No Catalog foreign-table access.

## Verification
Domain/persistence/contract/tenant isolation/harness.

## Architecture / security / reliability / observability / local runtime
Procurement owns commitment only. Historical identifiers/snapshots immutable.

## Risks and edge cases
Product archived between draft and submit; revalidate at submit.

## Open questions
None.

Completed 2026-08-14. Added Procurement module/table, Supplier/PO aggregates, immutable Submitted transition, tenant-scoped DynamoDB adapter, and Catalog producer-owned purchasability query contract. Submission tests verify active Supplier and eligible Product revalidation without Catalog foreign-table access.
