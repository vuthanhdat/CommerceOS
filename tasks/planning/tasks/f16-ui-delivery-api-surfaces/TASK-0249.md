## Objective
Implement the merchant Catalog screens required to create, classify, enrich, publish and maintain Products from Backoffice.

## Screens
- BO-10 `/app/catalog/products` Product list.
- BO-11 `/app/catalog/products/new` and `/app/catalog/products/{id}` Product create/edit.
- BO-12 `/app/catalog/references` Categories & Brands.

## Required UI behavior
- Product list columns: image, name, SKU, base price, category, brand, status, revision/actions; search/filter and cursor pagination.
- Product editor sections: General, Classification, Specifications, Media; save with expected revision; publish/unpublish/archive actions gated by current state/capability.
- Category/Brand tabs: name/status/revision, create and retire.
- Surface domain errors such as publication prerequisites, SKU/slug conflict and stale revision without guessing server truth.
- Provide storefront preview link only when a safe public slug is available.

## Acceptance criteria
- [ ] Merchant can create a Draft Product, edit it, assign references/specifications/media and publish it.
- [ ] Published SKU immutability and lifecycle restrictions are reflected after server response.
- [ ] Stale revision prompts refresh/review rather than silently overwriting.
- [ ] Staff/Viewer mutation actions are hidden/disabled according to server-presented capability but server remains authoritative.
- [ ] Archived/retired records remain inspectable where the API allows and are not destructively deleted.
- [ ] Loading/empty/error/forbidden/conflict states are complete.
- [ ] Responsive/keyboard form and table behavior passes focused tests.
- [ ] Full harness passes.

## Verification
Backoffice component tests, Catalog browser journey against local API, frontend build, full harness.

## Architecture / security / reliability / observability / local runtime
Never let UI-side capability checks or route guards replace endpoint authorization. Use revision and server validation; no direct LocalStack SDK calls from frontend.

## Risks and edge cases
Concurrent editors, large specification lists, image reorder, publication after reference retirement, slug normalization differences.
