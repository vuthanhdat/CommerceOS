## Objective
Implement Inventory Backoffice screens that let merchants inspect authoritative stock by warehouse, administer warehouses, review movement evidence and perform permitted stock adjustments.

## Screens
- BO-30 `/app/inventory/stock`.
- BO-31 `/app/inventory/warehouses`.
- BO-32 `/app/inventory/movements`.
- BO-33 stock-adjustment dialog from Stock.

## Required UI behavior
- Stock table: Product, Warehouse, OnHand, Reserved, Available; product/warehouse filters; adjustment action.
- Warehouses: Name, Status, Revision; create, disable, reactivate; show plan limit errors clearly.
- Movements: OccurredAt, Product, Warehouse, Type, Quantity, Source, CorrelationId with filters/pagination.
- Adjustment dialog: Product, Warehouse, Increase/Decrease, Quantity, required safe source/reason identity; never expose reserve/release/issue as manual shortcuts unless a later approved workflow requires it.

## Acceptance criteria
- [ ] OnHand/Reserved/Available are displayed directly from Inventory authority and visually distinguish reserved from available stock.
- [ ] Warehouse lifecycle actions refresh revision/state after success and handle stale conflict.
- [ ] LimitReached is presented as an entitlement/resource limit rather than generic server failure.
- [ ] Adjustment validation rejects zero/negative quantities client-side for usability while server remains authoritative.
- [ ] Insufficient available stock/adjustment conflict gets actionable feedback without retry loops.
- [ ] Movement history supports operational traceability and correlation display/copy.
- [ ] Loading/empty/error/forbidden states and responsive tables/dialogs are covered.
- [ ] Focused browser tests and full harness pass.

## Verification
Backoffice component/browser tests, local API/LocalStack inventory journey, frontend build, full harness.

## Architecture / security / reliability / observability / local runtime
Do not compute stock from UI event history or issue direct LocalStack calls. Capability guards are presentation only. Preserve source/correlation evidence.

## Risks and edge cases
Rapid stock changes, stale rows, very large quantities, disabled warehouse, long movement history.
