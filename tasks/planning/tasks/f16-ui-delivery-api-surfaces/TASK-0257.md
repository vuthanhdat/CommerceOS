## Objective
Expose the existing Accounting and Reporting capabilities through tenant-scoped HTTP/read models required by Dashboard, Chart of Accounts, Journals, General Ledger, Trial Balance and Reports screens.

## Scope
- Account list read model plus existing bootstrap/add-non-control/deactivate commands.
- Journal list/detail plus post/reverse delivery; preserve immutable posted journals.
- General Ledger endpoint with date range/cursor.
- Trial Balance endpoint with through date.
- Operational KPI endpoint with from/through business dates.
- Financial report endpoint using existing read-only Accounting reporting contract.
- Refund progress query where approved.
- Reporting projection checkpoint/freshness metadata sufficient to communicate eventual consistency without pretending transactional freshness.

## Candidate HTTP surface
`/api/v1/accounting/accounts`, `/journals`, `/general-ledger`, `/trial-balance`; `/api/v1/reports/operational-kpis`, `/financial`, `/refund-progress/{id}` and a projection-freshness/checkpoint resource as appropriate.

## Acceptance criteria
- [ ] Account list distinguishes control/non-control role/status and does not allow control-account deactivation.
- [ ] Journal list/detail exposes balanced immutable lines and traceable source/reversal metadata.
- [ ] Manual post/reverse commands use server validation and never edit an existing Journal.
- [ ] General Ledger and Trial Balance use Journal effective-date semantics.
- [ ] Operational KPI uses Tenant business date and current producer-owned projection data.
- [ ] Reporting freshness/checkpoint is explicit so UI can distinguish projection lag from zero business activity.
- [ ] Read endpoints are tenant-scoped; no cross-domain persistence shortcuts are added.
- [ ] HTTP/date/pagination/authorization tests and full harness pass.

## Verification
Accounting/Reporting application tests, HTTP tests, tenant/date boundary tests, LocalStack persistence/projection tests where relevant, full harness.

## Architecture / security / reliability / observability / local runtime
Accounting remains financial authority; Reporting is read-only projection authority for approved views. UI/API must not recalculate journals from operational tables. LocalStack only.

## Risks and edge cases
Large ledger history, date boundary in Tenant timezone, projection lag, reversal display, empty trial balance.

Record endpoints/DTOs, freshness semantics and verification.
