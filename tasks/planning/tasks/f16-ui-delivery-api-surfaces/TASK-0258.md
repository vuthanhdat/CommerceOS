## Required UI behavior

Accounting: account role/status/control marker and permitted actions; journal metadata/lines/debits/credits/reversal; GL date filters/cursor; Trial Balance through-date/account balances. Reports: operational and financial views plus refund progress where useful.

## Acceptance criteria
- [ ] Dashboard distinguishes projection freshness/lag from business zero values.
- [ ] Financial numbers are rendered from server read models and not recomputed from unrelated client datasets.
- [ ] Posted Journal is never editable; corrections use reverse/post actions only.
- [ ] Debits/credits remain visibly balanced per Journal and Trial Balance totals are understandable.
- [ ] Control-account restrictions are clear before action, with server authority preserved.
- [ ] Date filtering uses Tenant business semantics supplied by backend.
- [ ] Large tables support cursor/load-more without loading all history into browser memory.
- [ ] Loading/empty/error/forbidden states and responsive/accessible tables/forms are covered.
- [ ] Browser tests cover dashboard load, journal detail/reversal conflict, GL and Trial Balance filters.
- [ ] Full harness passes.
