## Objective
Implement Procurement Backoffice screens for supplier administration, purchase commitments, goods receipt/corrections and supplier invoice/payment evidence.

## Screens
- BO-40 `/app/purchasing/suppliers`.
- BO-41 `/app/purchasing/orders` and `/app/purchasing/orders/{id}`.
- BO-42 `/app/purchasing/orders/{poId}/receipts`.
- BO-43 `/app/purchasing/invoices` and invoice detail/dialog.

## Required UI behavior
- Suppliers: DisplayName, Status, Revision; create/archive.
- PO list/detail/editor: Supplier, Product/name/SKU snapshot, Quantity, UnitPriceVnd, line totals, total, status/revision; Draft create/edit; submit; approved cancel only.
- Receipts: PO context, Product, quantity, Warehouse, status, corrections; create/confirm/correct with immutable-history explanation.
- Invoices: SupplierReference, PO, InvoiceDate, ExpectedAmountVnd, AmountVnd, variance/status, payment evidence; record invoice, approve variance when authorized, record payment.

## Acceptance criteria
- [ ] UI never allows editing a submitted immutable PO as if it were Draft.
- [ ] Receipt corrections are presented as compensating evidence, not destructive edits.
- [ ] Invoice variance is visible before approval and approval is capability-gated.
- [ ] Supplier payment UI clearly represents external attestation/evidence rather than real fund transfer.
- [ ] Product/Supplier stale/ineligible conflicts are surfaced from server truth.
- [ ] Totals displayed by UI match server data and are not submitted as authority where server derives them.
- [ ] Loading/empty/error/forbidden/conflict states are complete.
- [ ] Responsive forms/tables and key browser journeys are tested.
- [ ] Full harness passes.

## Verification
Backoffice component/browser tests for Supplier -> Draft PO -> Submit -> Receipt -> Invoice -> Variance/Payment path, frontend build, full harness.

## Architecture / security / reliability / observability / local runtime
UI does not write Inventory or Accounting directly. Downstream effects remain event/application integrations owned by backend modules.

## Risks and edge cases
Long PO lines, correction history, stale revisions, archived Supplier, invoice variance, duplicate submit/payment evidence.
