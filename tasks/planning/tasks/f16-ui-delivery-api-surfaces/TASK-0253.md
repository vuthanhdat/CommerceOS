## Objective
Provide tenant-scoped Warehouse, StockItem and StockMovement list/read surfaces plus the missing explicit adjustment command needed by Inventory Backoffice.

## Scope
- Warehouse list read model with status/revision and create/disable/reactivate HTTP commands.
- Stock list projection keyed by Product + Warehouse with OnHand/Reserved/Available and cursor/filter support.
- StockMovement list projection with occurred time, type, quantity, source and correlation id.
- Explicit adjustment-increase application command if absent; expose increase/decrease adjustment through one safe merchant HTTP contract without bypassing Inventory invariants.
- Product identity/name enrichment only through explicit Catalog read contracts or an owner-safe projection; never Catalog table access.

## Candidate HTTP surface
`GET/POST /api/v1/inventory/warehouses`; disable/reactivate actions; `GET /api/v1/inventory/stock?warehouseId=&productId=&cursor=`; `GET /api/v1/inventory/movements?...`; `POST /api/v1/inventory/adjustments`.

## Acceptance criteria
- [ ] Stock list preserves `Available = OnHand - Reserved` and never presents a negative authoritative quantity.
- [ ] Warehouse create/reactivate continues to enforce current entitlement limit using Inventory-owned count.
- [ ] Warehouse list includes Disabled records needed for reactivation/history.
- [ ] Stock adjustments are source-idempotent where current operation design requires it and create movement evidence.
- [ ] Adjustment decrease cannot consume reserved stock; increase follows domain math.
- [ ] Movement query is tenant-scoped and filterable without cross-domain persistence reads.
- [ ] HTTP conflict/insufficient-stock/limit/not-found mappings are tested.
- [ ] Full harness passes.

## Verification
Inventory application/domain tests, HTTP tenant/concurrency tests, LocalStack conditional-write/persistence tests, full harness.

## Architecture / security / reliability / observability / local runtime
Inventory remains the quantity authority; UI/read models do not recalculate business truth from event history. Correlation/source identity is preserved for movements. LocalStack only.

## Risks and edge cases
Concurrent reservations during stock list refresh, disabled warehouse with stock history, adjustment retry, large movement history.
