## Objective
Expose the existing anonymous Storefront/Catalog/Inventory/Pricing/checkout capabilities through safe public HTTP endpoints and enrich public list/detail DTOs enough for the planned Storefront screens.

## Scope
- Public storefront profile read: slug, safe display name/status/public configuration fields actually approved.
- Product list endpoint with search/cursor and approved public image/classification/availability/base/effective-price/promotion presentation.
- Product detail endpoint with approved media, Category/Brand labels, specifications, availability and Pricing presentation.
- Checkout validate endpoint preserving authoritative repricing/reconfirmation.
- Idempotent guest order placement endpoint.
- Order-confirmation response sufficient for the immediate browser success screen.
- Safe failure semantics for unknown/suspended storefront, unsellable Product, unavailable inventory, Pricing unavailable, invalid checkout, reconfirmation and idempotency conflict.

## Candidate HTTP surface
- `GET /api/v1/storefronts/{storefrontSlug}`
- `GET /api/v1/storefronts/{storefrontSlug}/products?search=&cursor=&pageSize=`
- `GET /api/v1/storefronts/{storefrontSlug}/products/{productSlug}`
- `POST /api/v1/storefronts/{storefrontSlug}/checkout/validate`
- `POST /api/v1/storefronts/{storefrontSlug}/orders`

Do not add anonymous `GET order by id` unless a separate safe guest-access capability is explicitly designed.

## Acceptance criteria
- [ ] Suspended/unknown Tenant cannot expose catalog or accept checkout.
- [ ] Public Product DTO exposes only approved public fields and managed media, never internal persistence/source/advisory data.
- [ ] Public effective price comes from current Catalog + Pricing authority and a Promotion never overrides sellability.
- [ ] Availability comes from Inventory-owned query contracts.
- [ ] Checkout ignores browser total/discount authority and forces reconfirmation on authoritative price change.
- [ ] Repeated equivalent placement with the same idempotency identity creates at most one Order.
- [ ] Storefront list/detail support the information required by SF-01/SF-02 without frontend cross-domain calls.
- [ ] HTTP tests cover not-found/suspended/unavailable/reconfirmation/conflict paths.
- [ ] Full harness passes.

## Verification
Application/contract tests, HTTP integration tests, Pricing/checkout regression, configured LocalStack tests where persistence is touched, full harness.

## Architecture / security / reliability / observability / local runtime
Anonymous routing derives trusted `PublicTenantContext` from slug/current Tenant state. Do not accept public `tenantId` authority. Preserve correlation and idempotency. LocalStack is the only infrastructure runtime.

## Risks and edge cases
Promotion boundary instant, base-price change between list and checkout, Product unpublish after cart, stock loss after cart, missing media asset, duplicate browser submit.

## Open questions
No new anonymous order-history capability is authorized by this task.
