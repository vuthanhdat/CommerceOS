## Out of scope

## Inputs

## Implementation steps
Implement provider model/API/idempotency, scenario engine, signed delivery/retry, stable query, failure controls and scenario tests.

## Acceptance criteria
- [ ] Same idempotency key + equivalent request returns prior result; incompatible reuse rejects.
- [ ] Timeout-after-commit can commit Captured then make caller time out.
- [ ] Delayed/duplicate/out-of-order webhook scenarios are deterministic.
- [ ] Provider query reveals committed state for reconciliation.
- [ ] Webhook delivery failure is independently retryable/DLQ-capable when queue mapping is introduced.
- [ ] No real payment data is accepted/stored.
