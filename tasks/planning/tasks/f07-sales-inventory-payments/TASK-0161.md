## Objective
Create Inventory ownership for Warehouses and quantity state with current MaxWarehouses hard-limit enforcement.

## Scope
Inventory module/table; Warehouse lifecycle required by MVP; active-Warehouse count/guard; StockItem identity/state; trusted Tenant/Product/Warehouse access patterns; strong mutation reads and conditions.

## Out of scope
Reservation/movements, Accounting value, negative stock/backorder.

## Inputs
Inventory domain baseline, persistence access patterns, entitlement contract.

## Expected changes
Inventory module/CDK/tests.

## Implementation steps
Model Warehouse/StockItem, owner count guard, entitlement check at create/reactivate, key/access patterns, tenant isolation and concurrent final-slot tests.

## Acceptance criteria
- [ ] Inventory owns Warehouse count and stock quantity truth.
- [ ] Current MaxWarehouses is obtained from SubscriptionBilling, not stored as Inventory authority.
- [ ] Concurrent create/reactivate cannot exceed hard limit.
- [ ] Existing Warehouses are never auto-deleted/deactivated on downgrade.
- [ ] StockItem base state preserves non-negative invariant foundation.
- [ ] No Catalog/Subscription foreign-table read.

## Verification
Unit/DynamoDB concurrency/tenant isolation/CDK/harness.

## Architecture / security / reliability / observability / local runtime
Tenant/Product IDs are identifiers, not authorization; owner-local transaction protects count.

## Risks and edge cases
Concurrent entitlement change/create; coordinate via approved owner-boundary pattern, not distributed transaction.

None.
