## Objective
Accept merchant cancellation before Fulfilled while preserving Sales truth separately from Inventory release and any required approved payment refund operation.

## Scope
Sales cancel authorization/idempotency/revision; OrderCancelled fact; reservation release consumer/command; captured-payment handling via approved refund path/intent as applicable; progress visibility.

## Out of scope
Cancellation after Fulfilled, shopper self-service, treating cancellation as proof of release/refund completion.

## Inputs
PD-042, Inventory/Payments contracts, refund boundary.

## Expected changes
Sales/Inventory/Payments integration contracts/consumers/tests.

## Implementation steps
Implement precondition and Sales fact, independently apply release when reserved, preserve Payment captured/Unknown rules, expose partial downstream progress safely.

## Acceptance criteria
- [ ] Owner/Admin/Staff may cancel only before Fulfilled according to domain authority.
- [ ] Accepted cancellation is idempotent and Sales-owned.
- [ ] Reserved stock release is separate/source-idempotent.
- [ ] Captured payment is not silently marked refunded by cancellation.
- [ ] OutcomeUnknown prevents unsafe financial conclusions.
- [ ] Partial failure remains observable/recoverable.

## Verification
State/authorization/source replay/failure integration/harness.

## Architecture / security / reliability / observability / local runtime
No cross-domain transaction; producer facts/commands only.

## Risks and edge cases
Cancellation racing with fulfillment/payment evidence.
