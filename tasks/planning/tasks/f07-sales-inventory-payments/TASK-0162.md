## Objective
Implement concurrency-safe source-idempotent physical/reservation operations preserving `Available = OnHand - Reserved >= 0`.

## Scope
Reserve all required Order quantities; release; issue; receive; adjustment increase/decrease with reason; immutable StockMovement; StockReservation lifecycle; source claims; low-stock transition hook.

## Out of scope
Accounting valuation, backorder, partial allocation/fulfillment, manual release of payment-Unknown holds without evidence.

## Inputs
Inventory domain rules, INV access patterns.

## Expected changes
Inventory Domain/Application/Infrastructure plus tests.

## Implementation steps
Encode invariant and movement math, implement conditional/bounded transactions, source identities and reservations, whole-order reservation result, adjustment guard `OnHand >= Reserved`, duplicate/concurrent tests.

## Acceptance criteria
- [ ] OnHand/Reserved/Available invariants hold under concurrency.
- [ ] Insufficient stock cannot oversell the final unit.
- [ ] Reserve/release/issue/receive/return/adjust logical source replays apply at most once.
- [ ] Issue decreases both OnHand and Reserved; release decreases Reserved only.
- [ ] Downward adjustment cannot consume Reserved stock.
- [ ] Every accepted physical non-zero effect has immutable movement evidence.
- [ ] Payment OutcomeUnknown hold is not released by time alone.

## Verification
Heavy unit property/scenario tests; concurrent LocalStack DynamoDB tests; duplicate/source tests; harness.

## Architecture / security / reliability / observability / local runtime
No unprotected read-then-write. Movement diagnostics retain source/correlation, not foreign persistence pointers.

## Risks and edge cases
Whole-order line cardinality may exceed one bounded transaction; if real approved cardinality does, create a focused Inventory coordinator design task rather than inventing a product line limit.
