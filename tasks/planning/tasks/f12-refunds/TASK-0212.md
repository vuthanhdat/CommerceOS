## Objective
Reliably publish versioned RefundApproved fact to independent Inventory, Payments and Accounting consumer queues without a global refund workflow/state.

## Scope
Atomic Sales approval+outbox; consumer-required event data; change-feed relay; EventBridge-style route; consumer queues/DLQs; version handling/redrive identity; delivery diagnostics.

## Out of scope
Global RefundCompleted, Inventory/payment/accounting implementation, best-effort publish after commit.

## Inputs
ADR-011, ADR-006, RefundApproved contract.

## Expected changes
Sales outbox and integration CDK/routes/contracts/tests.

## Implementation steps
Finalize event schema/version, publish reliably, create named consumer routes/queues only, test producer interruption, duplicate fan-out, poison/version handling and redrive.

## Acceptance criteria
- [ ] Refund approval and its outbox are atomic in Sales ownership.
- [ ] Event contains approved amount/currency/returned line quantities and stable original references required by consumers, not table pointers/provider secrets.
- [ ] Each consumer has independent retry/DLQ.
- [ ] Duplicate/redrive preserves same logical event/source/correlation identity.
- [ ] One consumer failure does not roll back Sales approval or another consumer success.
- [ ] No global refund completion authority is introduced.

## Verification
Contract/unit + LocalStack Streams/EventBridge/SQS/DLQ failure tests + harness.

## Architecture / security / reliability / observability / local runtime
At-least-once explicit; queue state operational only. Safe diagnostics per consumer.

## Risks and edge cases
Consumer version rollout and LocalStack routing fidelity.
