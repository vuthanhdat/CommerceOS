## Objective
Post the three approved append-only refund Accounting effects independently and provide non-authoritative progress visibility across domains.

## Scope
RefundApproved -> Dr Revenue/Cr Deposits for recognized sale; StockReturned -> Dr Inventory/Cr COGS using Accounting original issue-cost provenance; PaymentRefunded -> Dr Deposits/Cr Cash; source claims/reversal links; reporting/support progress projection.

## Out of scope
Editing original journals, treating approval as cash refund proof, global RefundCompleted business state.

## Inputs
PD-023, ADR-011, Accounting consumers.

## Expected changes
Accounting consumers/journals and Reporting projection/tests.

## Implementation steps
Implement three independent source postings, find original issue cost in Accounting-owned provenance, enforce caps/links, build projection of per-domain observed progress, test delivery permutations.

## Acceptance criteria
- [x] RefundApproved revenue compensation posts once and never Cash.
- [x] StockReturned reverses COGS at original Accounting issue-cost basis once.
- [x] PaymentRefunded clears Deposits/Cash only after verified provider fact.
- [x] Original journals remain immutable and corrections link back.
- [x] Any delivery order/duplicate does not create unbalanced/duplicate posting.
- [x] Progress projection is labeled non-authoritative and tolerates partial completion.

## Verification
Accounting unit/persistence/consumer permutation/rebuild/LocalStack routes/harness.

## Architecture / security / reliability / observability / local runtime
Accounting never reads Sales/Inventory/Payments tables. Missing predecessor provenance becomes retry/NeedsAttention.

## Risks and edge cases
StockReturned may arrive before required original posting is visible; consumer must recover safely.

## Open questions
None.

## Completion report
Completed 2026-08-14: Accounting now accepts the three distinct refund facts, locates only its own original journal provenance, posts linked balanced corrections, and preserves source dedupe. Reporting has a separate partial-progress projection that never asserts a global refund-completed state.
