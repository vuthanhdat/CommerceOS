## Objective
Consume verified commerce facts exactly once to post approved deposit, revenue and COGS entries using Accounting-owned weighted-average valuation.

## Scope
`PaymentCaptured` -> Dr Cash/Cr Customer Deposits; `OrderFulfilled` -> Dr Deposits/Cr Revenue; `StockIssued` -> Dr COGS/Cr Inventory; weighted-average receipt/issue state needed for issued cost; source claims/inbox; immutable provenance.

## Out of scope
Posting revenue on OrderConfirmed, using Catalog advisory cost, reading Sales/Inventory tables.

## Inputs
PD-020/021, resolved cost-pool scope, producer facts.

## Expected changes
Accounting consumers/valuation persistence/contracts/tests and reliable routes as coordinated with TASK-0195.

## Implementation steps
Define consumer-required versioned fact data, implement source-idempotent posting, maintain valuation state on accepted cost evidence, snapshot issue cost, test duplicate/out-of-order and balance/provenance.

## Acceptance criteria
- [x] PaymentCaptured posts deposit, not revenue.
- [x] Whole OrderFulfilled is the revenue trigger once.
- [x] StockIssued is the single COGS trigger for that physical issue.
- [x] Issue cost uses Accounting-owned weighted-average state, never Catalog cost.
- [x] Duplicate facts create no duplicate journal/valuation effect.
- [x] Accounting never reads producer persistence.
- [x] Every automated posting is balanced and traceable to source fact.

## Verification
Unit valuation math; consumer duplicate/out-of-order; persistence transaction; LocalStack route integration where available; harness.

## Architecture / security / reliability / observability / local runtime
At-least-once consumers. Missing required provenance becomes recoverable failure/NeedsAttention, not guessed posting.

## Risks and edge cases
Out-of-order fulfillment/issue/payment facts; valuation receipt evidence sequencing.

## Open questions
Handled by resolved TASK-0190 dimension.

## Completion report
Version-one inbound facts post Cash/Deposits, Deposits/Revenue and COGS/Inventory independently. Receipt-derived moving average state and the source claim are committed with the Accounting effect; replay is duplicate-safe.
