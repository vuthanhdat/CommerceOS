## Objective
Provide repeatable safe inspection/recovery for poison messages, stuck Unknown/NeedsAttention work and failed projections without editing business state directly.

## Scope
Queue/DLQ inventory; inspect command/query; failure reason/correlation/source display; redrive preserving logical identity; bounded replay controls; provider/workflow reconciliation trigger where project contracts allow; test fixtures/runbook.

## Out of scope
Changing event IDs on redrive, manually declaring provider success/failure, deleting evidence to make queues green.

## Inputs
All introduced async routes, observability conventions, LocalStack lifecycle tooling.

## Expected changes
`tools/commerceos.py` or equivalent operator tooling, application support contracts, tests/docs after inspection.

## Implementation steps
Inventory operational recovery cases, define safe project-owned commands, implement inspection/redrive/reconcile actions, test poison/temporary failure/repeated redrive and task-instance isolation.

## Acceptance criteria
- [x] DLQ item can be correlated to original event/source/consumer failure.
- [x] Redrive preserves event/source/correlation/causation identity.
- [x] Duplicate redrive remains safe because consumers are idempotent.
- [x] Provider Unknown recovery uses inquiry/reconciliation, not manual outcome mutation.
- [x] Tooling is tenant/platform authorization aware where business query context is needed.
- [x] LocalStack task instance resources are not mixed accidentally.

## Verification
Failure-injection LocalStack tests + CLI/tool tests + harness.

## Architecture / security / reliability / observability / local runtime
Operational tooling invokes project contracts; no direct foreign-table mutation shortcut. Safe diagnostics only.

## Risks and edge cases
Repeated poison redrive loops; require explicit bounded action and diagnostics.
