## Objective
Provide a responsive tenant-bound cart whose contents/prices are explicitly non-authoritative until checkout validation.

## Scope
Add/remove/update whole-unit quantities; Tenant binding; displayed Product snapshot/estimated totals; persistence strategy appropriate to current frontend; validation of basic quantity shape; checkout handoff.

## Out of scope
Server-authoritative final price, discount authority, inventory reservation, shopper account.

## Inputs
Storefront Product DTOs, whole-unit/VND rules.

## Expected changes
Storefront frontend and minimal cart application/state code found through inspection.

## Implementation steps
Model tenant-bound cart lines, immutable ProductId reference + display estimate, quantity operations, clear/change-Tenant behavior, unit/UI tests.

## Acceptance criteria
- [x] Cart never treats browser price/total as authoritative checkout data.
- [x] Quantities are positive whole units.
- [x] Cart cannot silently mix multiple Tenants.
- [x] Product removal/update is deterministic and accessible in UI.
- [x] Checkout handoff sends identifiers/intent, not trusted tenant/price authority.

## Verification
Frontend lint/unit/build; integration with storefront reads; harness.

## Architecture / security / reliability / observability / local runtime
Client state is untrusted input; no sensitive payment data.

## Risks and edge cases
Product unpublish/price change after item added; resolved at checkout, not cart mutation.

## Open questions
Exact client persistence mechanism follows current frontend conventions.

## Completion report
Completed 2026-08-14. Added tenant-bound transient cart state with whole-unit validation, deterministic updates/removal, and an explicitly non-authoritative estimate UI.
