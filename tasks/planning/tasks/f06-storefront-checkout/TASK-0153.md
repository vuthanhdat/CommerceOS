## Objective
Validate current sellability, price and stock availability server-side and require explicit shopper reconfirmation if any price changed.

## Scope
PublicTenantContext revalidation; producer-owned Catalog/Pricing query; current Inventory availability query; quantity/Money validation; refreshed totals; reconfirmation result contract; no Order on changed price.

## Out of scope
Reservation/capture, manual discount, accepting stale lower price silently.

## Inputs
Checkout domain rules and producer contracts.

## Expected changes
Storefront/Sales checkout application composition plus contracts/tests.

## Implementation steps
Accept untrusted cart intent, re-resolve Tenant, fetch authoritative Product/price/availability, calculate totals, compare shopper-confirmed estimates, return reconfirm-required or validated placement input.

## Acceptance criteria
- [ ] Client tenantId/price/total/discount cannot override owner truth.
- [ ] Every Product is currently Published/sellable for resolved Tenant.
- [ ] Inventory availability is checked without reserving yet.
- [ ] Any price difference, higher or lower, yields refreshed terms and no Order.
- [ ] Reconfirmation produces a new placement attempt using authoritative terms.
- [ ] Validation errors are safe/non-disclosing.

## Verification
Unit/contract/cross-Tenant/price-change/stock-change integration/harness.

## Architecture / security / reliability / observability / local runtime
Immediate owner queries stay synchronous. Correlation spans checkout composition.

## Risks and edge cases
Availability can change after validation; reservation task later is authoritative under concurrency.

## Open questions
No promotion rule in MVP; Pricing remains optional future owner.

## Completion report
Record repricing scenario evidence.
