## Objective
Make CI run the repository harness plus a bounded isolated LocalStack job for infrastructure-sensitive changes.

## Context
CI must not create a ceremonial cloud deployment pipeline; LocalStack is the only infrastructure target.

## Scope
CI workflow/job, isolation prefix/ports, bootstrap/deploy/smoke, diagnostics and cleanup; use existing repository entry points where practical.

## Out of scope
AWS credentials/OIDC, preview cloud accounts, deploying every future service now.

## Inputs
TASK-0100 verified commands; `docs/development/11-ci-cd-pipeline.md`.

## Expected changes
`.github/workflows` and/or repository verification tooling after inspection.

## Implementation steps
Define change/job trigger, start isolated LocalStack, deploy foundation, run selected smoke/integration check, collect diagnostics on failure, always clean up.

## Acceptance criteria
- [ ] CI uses no real AWS credential or endpoint.
- [ ] Job has unique resource/instance identity.
- [ ] Foundation deploy and smoke are repository-owned.
- [ ] Cleanup executes on success/failure where practical.
- [ ] Emulator limitations can be surfaced without marking unsupported behavior as AWS-equivalent.
- [ ] Existing fast CI remains usable.

## Verification
Workflow validation plus local equivalent where possible; harness.

## Architecture / security / reliability / observability / local runtime
No business truth in CI state. Synthetic credentials only. Logs retain useful phase diagnostics without secrets.

## Risks and edge cases
Runner Docker support and LocalStack startup time/resource limits.

## Open questions
Exact workflow split should follow current repository CI after inspection.

## Completion report
Record job names, triggers, commands and evidence.
