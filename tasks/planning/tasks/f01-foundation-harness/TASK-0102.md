## Objective
Make CI run the repository harness plus a bounded isolated LocalStack job for infrastructure-sensitive changes.

## Context
CI must not create a ceremonial cloud deployment pipeline; LocalStack is the only infrastructure target.

## Scope
CI workflow/job, isolation prefix/ports, bootstrap/deploy/smoke, diagnostics and cleanup; use existing repository entry points where practical.

## Out of scope
AWS credentials/OIDC, preview cloud accounts, deploying every future service now.

## Expected changes
`.github/workflows` and/or repository verification tooling after inspection.

## Implementation steps
Define change/job trigger, start isolated LocalStack, deploy foundation, run selected smoke/integration check, collect diagnostics on failure, always clean up.

### CI implementation

- `.github/workflows/localstack-integration.yml` adds the bounded
  `foundation-localstack` job. It runs on relevant launcher/CDK/workflow changes
  and manual dispatch, uses `localstack-test` instance `0077`, and has a
  15-minute timeout.
- The job installs the pinned LocalStack-aware CDK tooling, pulls
  `localstack/localstack:4.8.1`, records the repository-owned configuration,
  runs `lifecycle`, then records `inspect` evidence. It collects task-container
  diagnostics on failure and always runs the instance-scoped `destroy` command.
- Only synthetic `test` credentials and the LocalStack task endpoint created by
  the launcher are used. No AWS account, OIDC, deployment credential, or real
  endpoint is configured.
- `harness.yml` now installs .NET 10 and Node 24 before running the full harness,
  keeping the existing fast repository CI usable.

### Limitation statement
