## Objective
Make one logical registration intent converge to Active Tenant + initial Active Owner + 30-day Trial/EntitlementSet and never report complete while Trial is knowingly absent.

## Scope
Trusted onboarding context; verified email; BusinessProfile validation; Tenancy local transaction; idempotency/operation status; durable Trial work outbox; sync fast path to `StartTrialSubscription`; recovery worker; 202 pending status when interrupted.

## Out of scope
Cross-module DynamoDB transaction, destructive rollback, paid plan activation.

## Inputs
ADR-009, tenant/subscription baselines, persistence/integration architecture.

## Expected changes
Tenancy + SubscriptionBilling contracts, worker/queue mapping and tests.

## Implementation steps
Implement local registration transaction + work intent, invoke idempotent Trial, persist operation status, recover same logical source command, expose durable status.

## Acceptance criteria
- [x] Equivalent registration retry creates one logical Tenant/Owner/Trial outcome.
- [x] Incompatible idempotency reuse conflicts.
- [x] Completed response exists only after Trial acceptance is proven.
- [x] Interruption yields durable pending operation and recoverable work.
- [x] Recovery does not create duplicate Trial or rollback Tenant.
- [x] Trial terms exactly match approved EntitlementSet.

## Verification
Unit/contract; LocalStack DynamoDB+SQS recovery/duplicate tests; API integration; harness.

## Architecture / security / reliability / observability / local runtime
No client Tenant authority during onboarding. Work retry is bounded/idempotent; correlation joins API/worker/Subscription evidence.

## Risks and edge cases
Crash between local commit and sync call; duplicate worker; provider/module transient failure.

## Open questions
None; ADR-009 decides consistency mechanism.
