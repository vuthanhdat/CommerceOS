## Objective
Provide explicit platform-admin Tenant suspend/reactivate commands and privileged read-only support context without turning platform actors into Tenant Members.

## Scope
TrustedPlatformAdminContext/SupportReadContext; reason + expected revision; Active<->Suspended transitions; durable Audit intent; merchant read-only behavior; public/mutation denial hooks.

## Out of scope
Merchant self-suspension, closure/deletion, subscription mutation, bypass flag.

## Inputs
PD-004 domain/technical reconciliation, first-frontier contracts.

## Expected changes
Tenancy application/delivery authorization and tests; Audit intent contract only until Audit module exists.

## Implementation steps
Implement privileged context boundary, lifecycle commands, reason/revision/idempotency, read-only support queries, audit work intent and denial tests.

## Acceptance criteria
- [x] Only explicit platform-admin context can suspend/reactivate.
- [x] Reason is required and transition is revision/idempotency safe.
- [x] Suspension does not mutate Membership/Subscription/business history.
- [x] Merchant mutation/public commerce denied while approved reads remain role-limited.
- [x] Support path is read-only and cannot access foreign persistence directly.
- [x] Accepted/rejected security-significant actions produce durable Audit intent as required.

## Verification
Authorization/unit; LocalStack persistence; cross-context integration; harness.

## Architecture / security / reliability / observability / local runtime
High-privilege operation: explicit actor/correlation/reason/outcome diagnostics without unsafe payload disclosure.

## Risks and edge cases
Concurrent status transition and merchant request; audit delivery failure must recover.

## Open questions
None for MVP lifecycle.

## Completion report
Implemented separate `TrustedPlatformAdminContext` and `TrustedPlatformSupportReadContext` types; they cannot be substituted for merchant authority contexts. `TenantLifecycleAdministrationService` requires an operation identity, expected Tenant revision, actor correlation, and non-empty reason. The DynamoDB adapter commits an accepted Tenant status revision and source-owned `AUDITINTENT#TENANT-LIFECYCLE#...` record in one transaction. Rejected stale/invalid/not-found requests also leave a durable intent, while equivalent operation replay returns its original result. Membership and Subscription records are not rewritten. Existing merchant authority resolution continues to allow Active Membership reads for Suspended Tenants and denies merchant mutation.

Evidence: 25 Tenancy tests passed, including LocalStack verification of the atomic lifecycle/audit write, replay, and preserved Owner Membership.
