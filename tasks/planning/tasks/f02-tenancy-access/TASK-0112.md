## Objective
Implement concurrency-safe Membership administration and Invitation acceptance under last-owner and current MaxActiveMemberships rules.

## Scope
Owner/Admin/Staff/Viewer single-role model; activate/disable/reactivate/change role; owner guard/count guard; invitation issue/resend/revoke/accept/expiry; verified-email matching; entitlement query before growth.

## Out of scope
Custom permissions, automatic disabling on downgrade, tenant deletion.

## Inputs
Tenant domain baseline, first-frontier contracts, Tenancy access patterns, Entitlement contract.

## Expected changes
Tenancy Domain/Application/Infrastructure plus tests.

## Implementation steps
Implement aggregate/state rules, transactional guards/claims, invitation credential rotation/single use, count-limit integration, conflict/error semantics.

## Acceptance criteria
- [x] Exactly one current role per Membership.
- [x] Last Active Owner cannot be disabled/demoted/removed under concurrency.
- [x] Every Active role counts toward current hard membership limit.
- [x] Limit never auto-disables existing Memberships.
- [x] Only one pending invitation per normalized Tenant/email; resend invalidates prior credential.
- [x] Acceptance requires matching verified email, unexpired single-use credential and current capacity.
- [x] Disabled existing Membership is not silently reactivated by invitation.

## Verification
Unit concurrency cases; DynamoDB transaction/condition tests; tenant isolation; harness.

## Architecture / security / reliability / observability / local runtime
Invitation secret material must be safely stored/logged; idempotent acceptance/replay produces no duplicate membership.

## Risks and edge cases
Concurrent owner changes and simultaneous invitation acceptance at limit.

## Open questions
None material.

## Completion report
Completed 2026-08-14. Tenancy now maintains an owner-local active-membership/owner counter in the onboarding and membership transactions. Invitation credentials are SHA-256 digests, resend rotates the credential, and acceptance atomically consumes the invitation, subject authority records, Membership, and the active-count guard. Unit tests cover owner protection, current-limit denial, credential rotation/email matching, and disabled-member safety.
