## Objective
Establish PDI-owned DataSource policy/state so acquisition requires current platform approval plus Tenant enablement and, where scheduled, current entitlement.

## Scope
PDI module/persistence; DataSource identity/status/policy review evidence; platform enable/disable/current review; Tenant opt-in/out; kill switch; source limits configuration; authorization/read models.

## Out of scope
Crawler implementation, arbitrary platform bypass, automatic periodic policy expiry.

## Inputs
PD-026, PDI docs, technical baseline.

## Expected changes
PDI module/table/contracts/tests after inspection.

## Implementation steps
Model source governance states, platform-admin and Tenant commands, effective eligibility query, idempotency/revision, audit intent where privileged, persistence/access tests.

## Acceptance criteria
- [x] Platform policy approval and Tenant enablement are independent and both required.
- [x] Tenant cannot override platform Disabled/stale-policy state.
- [x] Source may be paused/disabled without affecting core commerce.
- [x] Policy review evidence is versioned/auditable; no arbitrary time expiry is invented.
- [x] Scheduled eligibility can additionally require current entitlement without moving source ownership.

## Verification
Unit/authorization/persistence/tenant isolation/harness.

## Architecture / security / reliability / observability / local runtime
Source-policy admin path explicit; no source credential/secrets in domain logs.

## Risks and edge cases
Material external policy changes make previously valid review stale.

## Open questions
Actual source policy must be rechecked in TASK-0141.

Completed 2026-08-14: PDI owns versioned source policy/review and tenant enrollment in a module-owned DynamoDB table. Unit tests cover disabled-source denial and scheduled eligibility requiring both enrollment and entitlement.
