## Objective
Create Audit ownership for append-oriented privileged/security evidence and authorized Tenant/platform query views without becoming business state authority.

## Scope
Audit module/table; evidence envelope; append/source dedupe; Tenant-visible Owner/Admin query policy; protected platform-security evidence separation; bounded pagination/time filters; retention consistent with MVP non-destructive policy.

## Out of scope
Event sourcing all domains, mutable audit records, exposing cross-Tenant denial details to merchants.

## Inputs
PD-033, Tenant Audit policy, integration architecture.

## Expected changes
Audit Domain/Application/Infrastructure/contracts/CDK/tests.

## Implementation steps
Model evidence fields/source identity/actor/context/outcome/reason/correlation, implement append idempotency and read policies, add cross-Tenant/non-disclosure tests.

## Acceptance criteria
- [x] Audit evidence is append-oriented/immutable for covered actions.
- [x] Duplicate source delivery does not duplicate logical evidence.
- [x] Owner/Admin Tenant view cannot reveal another Tenant/entity.
- [x] Platform-security evidence uses explicit privileged read path.
- [x] Audit acknowledgement/existence never becomes proof of underlying business success beyond recorded owner outcome.
- [x] Queries are bounded and Tenant/platform scoped.

## Verification
Unit/persistence/authorization/tenant isolation/LocalStack/harness.

## Architecture / security / reliability / observability / local runtime
High-sensitivity evidence; minimize stored secrets/payloads. Correlation/reason/source actor retained.

## Risks and edge cases
Auditing rejected cross-Tenant attempts without leaking target identity.

## Open questions
Retention beyond current MVP requires future privacy policy; do not invent TTL deletion.

## Completion report
Completed 2026-08-14: append-only evidence and source identity claims are stored transactionally in the Audit-owned table. Tenant reads require Owner/Admin trusted context, and platform-security evidence uses a separate explicit privileged path; tests cover dedupe and non-disclosure.
