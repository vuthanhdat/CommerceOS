## Objective
Provide per-recipient Unread/Read/Acknowledged notification truth for approved critical operational/security/billing/accounting exceptions.

## Scope
Notification module/table; recipient selection by current role/capability policy; event consumer(s); idempotent delivery record; read/ack commands; list/query; optional delivery adapter seam without requiring email.

## Out of scope
One shared Tenant read flag, acknowledgement resolving source exception, Viewer actionable notifications, mandatory external email provider.

## Inputs
PD-032 and named critical facts/projections available at implementation time.

## Expected changes
Notification Domain/Application/Infrastructure/frontend/contracts/tests.

## Implementation steps
Model per-recipient lifecycle, define source identity+recipient uniqueness, select recipients through trusted owner queries, consume named critical facts, implement read/ack/query.

## Acceptance criteria
- [x] One recipient action never changes another recipient state.
- [x] Acknowledged implies Read; replay is idempotent.
- [x] Owner/Admin receive approved Tenant-level critical notices; Staff only actionable operational notices; Viewer receives no actionable notice.
- [x] Notification acknowledgement does not mutate/resolve source-domain state.
- [x] Duplicate source delivery creates at most one logical notification per intended recipient.
- [x] Tenant isolation/query authorization is enforced.

## Verification
Domain/persistence/recipient-selection/duplicate/tenant/frontend tests; LocalStack route as applicable; harness.

## Architecture / security / reliability / observability / local runtime
Notification owns delivery/read state only; source details minimized to safe references/summaries.

## Risks and edge cases
Membership role changes between event time and delivery/query.

## Open questions
External channel delivery is future unless current UI needs it.

## Completion report
Completed 2026-08-14: Notification owns a per-recipient DynamoDB model and source+recipient dedupe key. Trusted recipient selection excludes Viewers and permits Staff only for actionable operational notices. The LocalStack foundation owns a notification queue/DLQ and named critical-fact route.
