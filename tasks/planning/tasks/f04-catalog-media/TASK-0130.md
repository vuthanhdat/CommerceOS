## Objective
Create the Catalog implementation boundary and module-owned persistence/access patterns without importing foreign business authority.

## Context
Catalog owns canonical Products; stock, accounting value and source snapshots remain outside it.

## Scope
Catalog Domain/Application/Infrastructure; Product base record/revision; Tenant-scoped repositories; claim pattern support; access-pattern ledger; module table/CDK when required.

## Out of scope
Full Product lifecycle rules, FilesMedia binary storage, PDI storage, storefront routing.

## Inputs
Catalog domain baseline, ADR-005, persistence access patterns.

## Expected changes
Catalog projects/table/tests after actual code inspection.

## Implementation steps
Create module boundary and ports; implement Tenant-keyed base access and claim primitives; prohibit Scan/foreign repository references; wire infrastructure and LocalStack tests.

## Acceptance criteria
- [ ] Catalog owns one implementation persistence boundary.
- [ ] Tenant-owned repository calls require trusted scope.
- [ ] Product IDs/route values never grant Tenant authority.
- [ ] Revision/conditional primitives support lifecycle/uniqueness tasks.
- [ ] No Catalog code reads Inventory/PDI/Accounting persistence.
- [ ] Access-pattern ledger and LocalStack persistence evidence exist.

## Verification
Architecture/unit/DynamoDB integration/CDK/harness.

## Architecture / security / reliability / observability / local runtime
Module boundary follows Domain <- Application <- Infrastructure. Diagnostics include Tenant/correlation only where safe. LocalStack endpoint configuration stays Infrastructure-only.

## Risks and edge cases
Avoid prematurely fixing physical schemas for later public/PDI queries not yet Ready.

## Open questions
Category/Brand historical name-reuse does not block module foundation.

## Completion report
Record access patterns, tests and limitations.
