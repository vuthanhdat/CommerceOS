## Objective
Implement the approved Product aggregate lifecycle and Tenant-unique SKU/slug invariants.

## Scope
Create/edit; VND Money/zero price; Draft/Published/Unpublished/Archived; publication eligibility; first-publication SKU freeze; permanent archived SKU claim; slug generation/edit/claim; optimistic revision.

## Out of scope
Stock sellability, discounts/promotions, redirects, variants.

## Inputs
`docs/domains/catalog.md`, CAT access patterns.

## Expected changes
Catalog Domain/Application/Infrastructure and tests.

## Implementation steps
Encode state/value rules; implement normalized claim transactions; preserve history/revision; add cross-Tenant, concurrent uniqueness and state-transition tests.

## Acceptance criteria
- [ ] Draft may omit SKU; first publish requires Name+SKU+valid VND Money.
- [ ] Zero price is valid; stock/category/brand/media are not publication prerequisites.
- [ ] SKU is case-insensitive Tenant-unique, immutable after first publish and never reusable after Archive.
- [ ] Published edits are live canonical edits; Published may Archive directly; Archived is terminal.
- [ ] Slug is Tenant-unique/mutable and never authorization.
- [ ] Later Catalog changes do not rewrite historical external facts.

## Verification
Domain/unit, concurrent DynamoDB claims, tenant isolation, API/contract as applicable, harness.

## Architecture / security / reliability / observability / local runtime
Uniqueness must use authoritative conditional/transactional claims, not eventual index alone. Safe conflict diagnostics.

## Risks and edge cases
Concurrent publish/SKU change/archive and slug collision.

None for Product rules.
