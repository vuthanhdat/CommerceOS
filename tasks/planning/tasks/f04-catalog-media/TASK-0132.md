## Objective
Implement flat Tenant-owned Category/Brand references and Product specification rules with non-destructive retirement.

## Scope
Create/rename/retire Category and Brand; normalized Tenant uniqueness; Product zero/one assignment; specifications unique by normalized name with value/unit/order; same-Tenant reference validation.

## Out of scope
Hierarchy, multiple categories, destructive cascade, private specifications.

## Inputs
Catalog domain baseline.

## Expected changes
Catalog domain/application/persistence plus tests.

## Implementation steps
Model reference lifecycles, claim records, rename transactions, assignment validation and specification collection rules; test retirement preserving Product references.

## Acceptance criteria
- [ ] Category/Brand normalized names are Tenant-unique.
- [ ] Product references at most one of each and cannot cross Tenant.
- [ ] Retirement preserves existing references/history and does not cascade Product mutation.
- [ ] Specification normalized names are unique within Product and display order is preserved.
- [ ] Public Product may expose approved Category/Brand/specification fields.

## Verification
Unit/persistence concurrency/tenant isolation/harness.

## Architecture / security / reliability / observability / local runtime
Catalog-only records; no foreign dependencies.

## Risks and edge cases
Historical normalized-name reuse after rename/retirement is unresolved only if implementation attempts reuse.

## Open questions
If a concrete implementation requires old-name reuse, stop and resolve OQ-004 rather than infer policy.

## Completion report
Record claim/retirement behavior.
