## Objective
Add an explicit Tenant-owned Customer/CRM profile capability while preserving immutable guest Order snapshots and avoiding automatic identity matching.

## Scope
Refine Customer aggregate/profile fields from existing product intent; CRUD/search/list; communication preferences/tags only where already approved/refined; optional explicit Order-Customer association that never rewrites historical snapshot; tenant isolation.

## Out of scope
Automatic guest-to-customer matching/creation, shopper authentication, inferred identity merge, marketing automation.

## Inputs
Product definition Customer Management and PD-035 guest rule.

## Expected changes
Customer module/contracts/persistence/frontend/tests after feature-level refinement/code inspection.

## Implementation steps
Confirm minimal Customer domain fields/commands before code, implement module/table and tenant-scoped queries, explicit link semantics if approved, protect Order snapshot immutability.

## Acceptance criteria
- [x] Guest checkout remains valid without Customer record.
- [x] No automatic Customer is created or matched from guest email/phone.
- [x] Customer identity/profile is Tenant-owned and cross-Tenant isolated.
- [x] No association is created in this slice, so accepted Order contact/commercial snapshots remain untouched.
- [x] Module does not become generic shared identity authority.

## Verification
Domain/persistence/tenant/API/frontend tests/harness.

## Architecture / security / reliability / observability / local runtime
Customer contact data is sensitive; minimize/log safely and define retention only when product policy exists.

## Risks and edge cases
Duplicate contact information is not automatically a uniqueness/identity key.

## Open questions
Minimal CRM field set and preferences should be refined immediately before implementation if current docs are insufficient.

## Completion report
Completed 2026-08-14. The approved minimal model is DisplayName required; Email/Phone optional; Email/SMS opt-in preferences. There are no tags, automatic contact matching, guest Order association or destructive privacy behavior. Customer has its own Domain/Contracts/Application/Infrastructure projects, tenant-owned DynamoDB table and cross-tenant/revision regression tests.
