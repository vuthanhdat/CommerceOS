## Objective
Integrate current entitlement limits with Tenancy/Inventory authoritative counters without transferring resource ownership to SubscriptionBilling.

## Scope
MaxActiveMemberships and MaxWarehouses query/use; owner-local conditional guard transactions; concurrency tests; error semantics; downgrade assessment query contract.

## Out of scope
Auto-disabling Membership/Warehouse, copied reporting count as authority.

## Inputs
Subscription, Tenancy and Inventory access-pattern baselines.

## Expected changes
Consumer application contracts/guards in owning modules plus tests.

## Implementation steps
Retrieve current entitlement, apply within owner command decision, atomically maintain owner counter/guard, test concurrent final slot and entitlement changes.

## Acceptance criteria
- [ ] All Active Membership roles count.
- [ ] Warehouse count is Inventory-owned.
- [ ] Concurrent growth cannot exceed current hard limit.
- [ ] Existing over-limit resources remain intact for remediation.
- [ ] SubscriptionBilling never writes owner resources/counts.
- [ ] Stale reporting count cannot authorize growth.

## Verification
Unit + LocalStack concurrent transaction tests + architecture/harness.

## Architecture / security / reliability / observability / local runtime
Trusted Tenant only; conditional conflicts are safe business outcomes and diagnosable.

## Risks and edge cases
Entitlement changes between read and owner commit require defined revalidation/guard pattern consistent with architecture.

## Open questions
Exact cross-module race fencing should follow technical contract; do not create distributed ACID.

## Completion report
Completed 2026-08-14. Membership and Warehouse growth paths evaluate the producer-owned current entitlement immediately before owner-local conditional transactions. Tenancy and Inventory retain their own counters and never auto-disable resources on lower limits; SubscriptionBilling receives no owner persistence access. Final-slot unit concurrency coverage verifies safe rejection.
