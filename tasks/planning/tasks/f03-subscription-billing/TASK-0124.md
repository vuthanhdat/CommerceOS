## Objective
Implement monthly activation/upgrade/downgrade/renewal/cancel/grace/end/reactivation exactly as approved, driven only by verified PlatformCharge evidence and authoritative usage checks.

## Scope
Paid activation; billing anchors/month-end; upgrade new period after success; scheduled downgrade and BlockedByUsage; cancel renewal; definitive renewal failure -> 7-day PastDue -> Ended; reactivation new period; Unknown reconciliation.

## Out of scope
Annual billing, proration, tax/statutory invoice, Enterprise, destructive resource remediation.

## Inputs
Subscription domain baseline and provider task.

## Expected changes
SubscriptionBilling aggregate/application/persistence/workers and tests.

## Implementation steps
Implement state/intent dimensions and expected revisions/idempotency, provider charge coordination, owner usage assessment contracts, period calculations, recovery/reconcile jobs.

## Acceptance criteria
- [x] Upgrade entitlements change only after verified successful required charge and start a fresh month.
- [x] Downgrade is next-renewal and blocked if authoritative hard-limit usage exceeds target.
- [x] No downgrade auto-deletes/disables foreign resources.
- [x] Cancel renewal does not end current paid period early.
- [x] Only definitive renewal failure creates PastDue; grace is exactly 7 days.
- [x] Unknown never becomes failure by time passage.
- [x] Ended preserves read/history/recovery and does not mutate Tenant/Membership.
- [x] Reactivation creates new accepted period/history.

## Verification
Extensive unit clock tests; provider failure/reconcile integration; duplicate commands; LocalStack persistence/worker; harness.

## Architecture / security / reliability / observability / local runtime
All tenant scoped; platform admin remains read-only support. Durable operations and unknown states observable.

## Risks and edge cases
Month-end anchors, retries at period boundary, simultaneous plan-change/cancel/renewal.

## Open questions
None in current approved product policy.

## Completion report
Implemented revision- and operation-protected paid Subscription current state with immutable
operation history. PlanVersions are resolved only from the SubscriptionBilling catalog; paid
terms become effective only after the dedicated SaaS `PlatformCharge` has verified success.
The month anchor clamps month-end dates correctly and a successful upgrade starts a fresh paid
period without proration.

| Scenario | Result |
|---|---|
| activation / upgrade / reactivation success | new accepted paid period and entitlement snapshot |
| charge timeout or missing evidence | `AwaitingChargeEvidence`; existing terms stay authoritative |
| definitive renewal no-commit | `PastDue` with exactly seven-day grace |
| grace expiry or cancelled period expiry | `Ended`; tenant/memberships/history untouched |
| scheduled restrictive downgrade over owner usage | `BlockedByUsage`; current terms continue; no foreign mutation |
| safe scheduled downgrade renewal | target terms apply only after charge success |

Usage is consumed only through `ISubscriptionUsageAssessor`, a producer-owned owner-domain
contract; application composition fails closed until those owner contracts are implemented.
Evidence: 22 SubscriptionBilling tests, including a LocalStack transactional current/history
and replay verification, passed.
