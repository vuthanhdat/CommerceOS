## Objective
Implement producer-owned `EvaluateEntitlement` so other modules receive only current trusted capability/limit decisions with provenance.

## Scope
Current Subscription/EntitlementSet lookup; approved keys; effective period/state evaluation; missing-entitlement fail-closed semantics; tenant-scoped query contract.

## Out of scope
Foreign module resource counts, plan-name checks, UI projection as authority.

## Inputs
Subscription baseline and first-frontier contract.

## Expected changes
SubscriptionBilling application/persistence and contracts.

## Implementation steps
Implement coherent current read, decision DTO, key/value validation, Trial/Active/PastDue/Ended effects, tests for boundaries and stale inputs.

## Acceptance criteria
- [x] EntitlementSet, not Plan name/client claim, is runtime authority.
- [x] Missing entitlement never implies enabled/unlimited.
- [x] Effective intervals/state are respected deterministically.
- [x] Ended removes ordinary operational entitlements while not changing Tenant/Membership state.
- [x] Consumers receive only required decision/provenance, not persistence models.

## Verification
Unit, LocalStack persistence integration, contract/architecture/harness.

## Architecture / security / reliability / observability / local runtime
Tenant scoped; no sensitive billing evidence exposed to ordinary consumers. Decision failures observable by correlation.

## Risks and edge cases
Boundary timestamps/period transitions; stale cached decision must not authorize a write.
