## Objective
Model PlatformCharge and a dedicated deterministic simulated SaaS billing provider that preserves verified success, definitive no-commit and OutcomeUnknown evidence.

## Scope
Provider port/app seam; charge aggregate/attempt identity; idempotency; deterministic scenarios; evidence validation/dedupe/non-regression; query/reconciliation.

## Out of scope
Merchant-order Mock Provider reuse, real money/card data, tax/invoice/proration.

## Inputs
PD-052 domain baseline, ADR-008 technical extension.

## Expected changes
SubscriptionBilling plus separate mock SaaS billing provider application; exact deployment files after inspection.

## Implementation steps
Define provider contract, implement deterministic test controls, stable operation identity, evidence ingestion and reconciliation, tests for timeout-after-commit/duplicates/out-of-order.

## Acceptance criteria
- [x] Provider seam is distinct from merchant Payments.
- [x] Equivalent retry has one logical charge effect; incompatible reuse conflicts.
- [x] Timeout/network/missing callback produces Unknown, never guessed failure.
- [x] Verified evidence is deduped and cannot regress known outcome.
- [x] Inquiry can converge Unknown when provider evidence exists.
- [x] No real payment data exists in model/fixtures.

## Verification
Unit/contract/integration/failure scenarios/harness; LocalStack only where infrastructure semantics are involved.

## Architecture / security / reliability / observability / local runtime

## Risks and edge cases

## Open questions

## Completion report
Added a `PlatformCharge` aggregate and `IPlatformBillingProvider` port, entirely separate from merchant-order Payments. The deterministic SaaS provider supports verified success, definitive no-commit, timeout-after-commit, network failure, and missing callback scenarios without payment instruments or real-provider credentials. A stable logical charge identity gives one effect for equivalent retry and rejects incompatible commercial reuse.

| Scenario | Immediate outcome | Reconciliation outcome |
|---|---|---|
| verified success | `Succeeded` | remains `Succeeded` |
| definitive no-commit | `DefinitivelyNotSettled` | remains definitive |
| timeout after commit | `OutcomeUnknown` | `Succeeded` from provider evidence |
| network failure / missing callback | `OutcomeUnknown` | remains Unknown without evidence |
| duplicate / out-of-order evidence | deduped | settled outcome never regresses |

DynamoDB records evidence transactionally with the charge revision; LocalStack tests verify dedupe and Unknown-to-success reconciliation. 17 SubscriptionBilling tests passed.
