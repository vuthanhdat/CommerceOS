## Readiness rules

Task maturity is independent of numeric order:

```text
Outline -> Refined -> Ready -> Active -> Completed
```

- **Outline** — useful future node; not executable.
- **Refined** — scope is materially understood, but one or more dependency/input/cloud gates still prevent execution.
- **Ready** — Builder-executable now under the repository Definition of Done.
- Only tasks explicitly marked `Ready` may be dispatched.
- Dependencies, human/product/domain/architecture/security/cost gates, cloud authorization, and exclusive-resource conflicts all fail closed.
- A task may become Ready later without renumbering the graph.
- Current approved domain/architecture baselines and accepted ADRs override stale wording in historical planning artifacts.

## Important V2 reconciliations

- Merchant onboarding includes separate Tenancy facts and the required 30-day Trial Subscription/Entitlement outcome; it is not the old tenant-only CRUD slice.
- Subscription & Billing is explicit backlog coverage and remains separate from shopper/order Payments.
- Catalog work follows the approved SKU, publication/archive, slug, flat Category/Brand, managed-media, and import-candidate semantics.
- Generic event infrastructure is not a standalone prerequisite. Reliable integration is introduced only with named producers/consumers under ADR-006.
- The order reservation/payment/allocation decision is no longer open: `TASK-0129` implements the named ADR-010 Step Functions Standard workflow when dependencies reach Ready.
- Refund effects follow ADR-011 choreography after Sales approval; V2 does not preserve the V1 assumption of a global returns workflow or `RefundCompleted` authority.
- Extraction tasks are conditional on measured architecture evidence and an accepted decision, not an assumed microservice destination.
- Real AWS work remains explicitly gated and cost-bounded.
- Task Orchestrator V1 is now implemented as local repository harness tooling. It consumes canonical planning state; it does not invent task semantics or replace the Backlog Planner.
- Orchestrator V1 includes a local dashboard and graceful Stop that stops new dispatch immediately while safely draining tasks already Active at stop-request time.
