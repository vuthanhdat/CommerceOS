## Runtime planning rule

ADR-012 is authoritative:

- LocalStack is the only infrastructure/runtime target;
- no task requires a real AWS account for development, staging, validation, or deployment;
- AWS account/region selection, AWS IAM/OIDC federation, AWS Budget/credit controls, cloud execution authorization, real-cloud preview/staging, and AWS teardown evidence are obsolete gates;
- AWS-style services remain valid capability mappings where LocalStack supports the required learning scenario;
- unsupported/partial/different LocalStack behavior must be documented rather than silently treated as AWS-equivalent;
- application/domain code remains independent of LocalStack-specific details.

The legacy `cloud_verification` metadata field remains temporarily in `BACKLOG.v2.yaml` for orchestrator/schema compatibility; under ADR-012 it means **infrastructure-sensitive verification against LocalStack**, never permission or a requirement to use real AWS.

## Readiness rules

Task maturity is independent of numeric order:

```text
Outline -> Refined -> Ready -> Active -> Completed
```

- **Outline** — useful future node; not executable.
- **Refined** — scope is materially understood, but one or more dependency/input/architecture gates still prevent execution.
- **Ready** — Builder-executable now under the repository Definition of Done.
- Only tasks explicitly marked `Ready` may be dispatched.
- Dependencies, human/product/domain/architecture/security gates, and exclusive-resource conflicts fail closed.
- Current approved domain/architecture baselines and accepted ADRs override stale wording in historical planning artifacts.

## Important V2 reconciliations

- Merchant onboarding includes Tenancy facts plus the required 30-day Trial Subscription/Entitlement outcome.
- Subscription & Billing remains separate from shopper/order Payments.
- Catalog work follows approved SKU/publication/archive/slug/Category/Brand/media/import semantics.
- Generic event infrastructure is not a standalone prerequisite; reliable integration is introduced only with named producers/consumers under ADR-006.
- `TASK-0129` implements ADR-010 durable order orchestration when its dependencies become Ready; Step Functions is an AWS-style capability mapping to LocalStack, not a real-AWS deployment requirement.
- Refund effects follow ADR-011 choreography; no global returns workflow or `RefundCompleted` authority is invented.
- Extraction tasks are conditional on measured architecture evidence, not an assumed microservice destination.
- Task Orchestrator V1 remains local repository harness tooling and does not invent task semantics.
- LocalStack bootstrap/reset/isolation and known emulator limitations are now explicit technical concerns.
